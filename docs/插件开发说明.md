# hopaw-agent 插件开发说明

> 适用范围：hopaw-agent 的「工具插件」（jar 动态插件）+ 前端组件注入（含沙箱容器）+ Hook 扩展体系。
> 阅读对象：需要新增 / 改造插件的开发者。
> 相关代码：`hopaw-contract`（契约）、`hopaw-infra`（插件加载与扫描）、`hopaw-app`（页面与控制器）、`hopaw-plugin-repo`（插件仓库）、`tools/*`（插件示例）。
> 版本口径：本文对应 **AgentPlugin 主体模型**（1 JAR = 1 插件 = 0..N 个工具集）。不存在旧格式兼容，插件 JAR 必须显式提供 `AgentPlugin` 实现。

## 1. 整体架构

### 1.1 两层主体：插件（AgentPlugin）与工具集（AgentTool）

```
AgentPlugin（插件主体，1 JAR = 1 实例）
 ├── 插件身份：id / name / version / author / url / description / icon / keyword
 ├── 插件生命周期：asyncInit() / destroy() / onConfigChanged()
 ├── 插件级配置：getConfigItems()  →  前缀 plugin.<id>.*
 ├── 工具工厂：getTools() → 0..N 个 AgentTool（插件自建实例，可注入共享资源）
 ├── 前端组件：plugin-assets.json（JAR 级）
 └── 通用调用：invoke(toolRef, params)

AgentTool（工具集，1 实现类 = 1 工具集）
 ├── getName() / getDescription() / getIcon() / getKeyword()
 ├── @Tool 方法 + @ToolSecurityLevel（给 LLM 的能力）
 ├── 工具级配置：getConfigItems()  →  前缀 tool.<name>.*
 └── 可选钩子：asyncInit() / destroy() / onConfigChanged()
```

要点：

- **注册表主键是 `pluginId`**，JAR 文件名只是物理定位属性（卸载删文件、读 assets 用）；
- **插件是工具的工厂**：插件先 `asyncInit()` 建共享资源（连接池、HttpClient…），再 `getTools()` 把资源注入工具实例——"工具先于插件 init"的时序问题在设计上不存在；
- **`getTools()` 返回空列表合法**：纯前端组件插件、纯 invoke 服务插件都是正当形态；
- 加载器拒绝条件：**JAR 内既没有 `AgentPlugin` 实现**即拒绝（纯前端插件也必须提供一个空工具的 `AgentPlugin`）。

### 1.2 数据流

```
                          ┌──────────── ① 工具调用（LLM → 后端 @Tool 方法）
用户 / LLM ──► AgentExecutor ──► AgentTool.@Tool(...)
                                      │
                                      │ ② 下发前端指令
                                      ▼
                     IWebSocketBridgeService.sendPluginCommand(userId, sessionId, payload)
                                      │  Spring Event → Artemis 队列 ws.plugin.cmd
                                      ▼
                         PluginWebSocketHandler → /ws/plugin（按 sessionId 定向）
                                      ▼
                         plugin-hook.js（window.PluginHook）→ 分发到插件 JS

   插件 JS 完成后 ──③ 回传结果──► POST /api/plugins/report ──► IPluginResultStore.complete()
                                                              │
       后端 @Tool 阻塞在 IPluginResultStore.await() 被唤醒 ◄────┘
```

另有 **invoke 双向通道**：`POST /api/plugins/{pluginId}/invoke`（body 可带 `toolRef` 路由到具体工具集）→ `AgentPlugin.invoke(toolRef, params)`，前端可直接按需向插件后端要数据，不走 @Tool / LLM。

前端组件注入是**独立于以上三通道**的第四条链路：应用启动时 `plugin-loader.js` 拉 `/api/plugins/assets?page=`，把 JAR 内声明的 css/js/html 注入页面（详见 §4）。

## 2. 插件工程骨架

以 `tools/hopaw-tool-database`（多工具集）与 `tools/hopaw-tool-chat-background`（纯前端）为模板：

```
tools/hopaw-tool-xxx/
├── pom.xml
└── src/main/
    ├── java/com/agent/hopaw/tool/xxx/
    │   ├── XxxPlugin.java                  # extends AbstractAgentPlugin（必须）
    │   ├── XxxFooTool.java                 # implements AgentTool（可选，0..N）
    │   └── XxxBarTool.java
    └── resources/
        ├── plugin-assets.json              # 前端资源清单（必须在 jar 根）
        └── static/
            ├── xxx.js / xxx.css / xxx.html # 前端逻辑与插槽 DOM
            └── icons/plugins/xxx.svg       # 插件图标
            └── icons/tools/xxx-foo-tool.svg# 工具集图标（可选）
```

### pom.xml 关键点

```xml
<parent>
    <groupId>com.hopaw.agent</groupId>
    <artifactId>hopaw-agent</artifactId>
    <version>1.0.0</version>
    <relativePath>../../pom.xml</relativePath>
</parent>
<packaging>jar</packaging>
<properties>
    <!-- 不安装到本地仓库，避免污染主工程依赖 -->
    <maven.install.skip>true</maven.install.skip>
</properties>
```

依赖（**全部 `provided`**，运行期由主工程提供）：

| 依赖 | 用途 | 何时需要 |
| --- | --- | --- |
| `com.hopaw.agent:hopaw-contract` | `AgentPlugin` / `AbstractAgentPlugin` / `AgentTool` / `IWebSocketBridgeService` / `IPluginResultStore` 等契约 | 必加 |
| `dev.langchain4j:langchain4j` | `@Tool` / `@P` / `InvocationParameters` | 有工具集时 |
| `org.springframework:spring-beans` | `@Autowired`（插件与工具实例都会被 `autowireBean` 注入） | 用到 `@Autowired` 时 |
| `com.alibaba.fastjson2:fastjson2` | JSON 序列化（下发指令 payload） | 用到时 |
| `org.slf4j:slf4j-api` | 日志 | 建议 |

> 常见坑：`@Autowired` **必须显式加 `spring-beans` 依赖**，否则报「程序包 org.springframework.beans.factory.annotation 不存在」。`spring-boot-starter` 会传递带入，但其它插件请照 `hopaw-tool-canvas` 的写法补 `spring-beans`。

构建插件：

- `maven-shade-plugin`：打 FAT jar，**排除** `dev.langchain4j:*` 与 `org.slf4j:*`（主工程已提供），并剔除 `META-INF/*.SF|DSA|RSA`、`module-info.class`；
- `maven-antrun-plugin`：`package` 阶段把产物复制到 `../../plugins/`；
- `<finalName>${project.artifactId}-${project.version}</finalName>`：保证产物名可预期。

> **只构建单个插件**：`mvn package -DskipTests -pl tools/hopaw-tool-xxx -am`（`-am` 一并构建父 POM 依赖链）。

### 加载与卸载契约

应用启动、Spring 容器就绪后，`JarPluginLoader`（`ApplicationReadyEvent`）：

1. 扫描 `${agent.plugin.dir:plugins}/*.jar`，按文件名排序加载；
2. `PluginClassLoader.scanAgentPluginClasses()` 找 `AgentPlugin` 实现；**找不到即拒绝**并记日志（提示"纯前端插件也应提供 getTools() 返回空列表的 AgentPlugin"）；
3. 实例化插件 → `beanFactory.autowireBean(plugin)` → `plugin.asyncInit()`；
4. `plugin.getTools()` 取工具实例 → 逐个 `autowireBean(tool)` → 逐个 `tool.asyncInit()`；
5. 以 `pluginId` 注册；**同 pluginId 已存在则拒绝**（升级必须走覆盖安装：卸载 → 写文件 → 加载）；
6. 同时解析 `plugin-assets.json` 缓存资源清单。

卸载（逆序）：逐个 `tool.destroy()` → `plugin.destroy()` → 关闭 classloader（释放 jar 文件句柄）。

## 3. 后端开发

### 3.1 AgentPlugin 接口

```java
public interface AgentPlugin {
    String getId();                                   // 插件唯一标识（注册表主键）
    String getDescription();
    default String getName()    { return getId(); }
    default String getVersion() { return "1.0.0"; }
    default String getAuthor()  { return "Agent Plugin"; }
    default String getUrl()     { return "https://gitee.com/hgflydream/hopaw-agent"; }
    default String getIcon()    { return "plugin.svg"; }   // jar 内 static/icons/plugins/
    default String getKeyword() { return ""; }
    default void asyncInit()    { }                   // 建插件级共享资源
    default void destroy()      { }                   // 释放自己创建并分发给工具的资源
    default List<ToolConfigItem> getConfigItems() { return List.of(); }   // plugin.<id>.*
    default void onConfigChanged() { }
    List<AgentTool> getTools();                       // 0..N，asyncInit 之后调用
    default Map<String, Object> invoke(String toolRef, Map<String, Object> params) {
        throw new UnsupportedOperationException("插件 " + getId() + " 不支持 invoke 调用");
    }
}
```

`AbstractAgentPlugin` 便捷基类收敛样板：

```java
public class DatabasePlugin extends AbstractAgentPlugin {
    private JdbcDriverRegistry driverRegistry;

    @Autowired private IPluginConfigService pluginConfigService;   // 插件级配置读取

    @Override public String getId() { return "database"; }
    @Override public String getDescription() { return "通用数据库操作插件：查询与结构管理"; }
    @Override public String getVersion() { return "2.0.0"; }
    @Override public String getIcon() { return "database.svg"; }

    @Override
    public void asyncInit() {
        driverRegistry = new JdbcDriverRegistry(...);    // 共享资源在插件级构建
        reloadRegistry();
    }

    @Override
    public void onConfigChanged() { reloadRegistry(); }   // 插件配置变更 → 重建共享资源

    @Override
    public List<AgentTool> getTools() {
        return tools(                                     // 把共享资源注入各工具集
                new DatabaseQueryTool(driverRegistry),
                new DatabaseSchemaTool(driverRegistry));
    }

    @Override
    public void destroy() { driverRegistry.close(); }
}
```

### 3.2 AgentTool 接口（已瘦身）

```java
public interface AgentTool {
    String TOOL_SEARCH_TOOL_NAME = "tool_search_tool";
    String DEFAULT_ICON = "agent-tool.svg";

    String getName();                                 // 工具集名，全局唯一
    String getDescription();
    default String getIcon()    { return DEFAULT_ICON; }   // jar 内 static/icons/tools/
    default String getKeyword() { return ""; }
    default void asyncInit()    { }
    default void destroy()      { }
    default List<ToolConfigItem> getConfigItems() { return List.of(); }   // tool.<name>.*
    default String getConfigPrefix() { return "tool." + getName() + "."; } // 框架统一约定
    default void onConfigChanged() { }
    // 已上移到 AgentPlugin：getVersion / getAuthor / getUrl / invoke / 插件生命周期 / 插件级配置
}
```

**工具集名（`getName()`）是全局唯一的**，Agent 绑定、前端 hook 过滤、工具执行列表分组都以它为准。
**保留 `getIcon/getKeyword/getConfigItems/asyncInit/destroy` 的理由**：内置工具（`hopaw-biz` 里的 `@Component` Bean，如 `AvatarTool`）**没有插件父节点**，仍需这些能力；同时多工具插件的各工具集理应有各自的图标与配置。

### 3.3 三种插件形态

| 形态 | `getTools()` | 典型例子 | 说明 |
| --- | --- | --- | --- |
| 单工具集 | 返回 1 个 | `ssh` / `dingtalk` / `file` … | 迁移主线，约 30 行插件样板 |
| 多工具集 + 共享资源 | 返回 N 个 | `database` → `databaseQuery` + `databaseSchema` | 共享 JDBC 驱动注册表由插件持有 |
| 零工具集（纯前端 / 纯 invoke） | 返回空 | `chat-background` | 只注入前端资产，需要 `sandbox:true`（见 §4.3） |

### 3.4 @Tool 方法规范

```java
@ToolSecurityLevel(ToolSecurityLevel.Level.SAFE)
@Tool(value = {"开始画布绘制", "在浏览器前端收缩会话区并新建一个并排的实时画布，返回确认信息"})
public String drawCanvas(
        @P("绘制说明，例如要绘制的内容主题") String description,
        InvocationParameters invocationParameters) {
    ...
}
```

| 写法 | 说明 |
| --- | --- |
| `@Tool(value = {...})` | **`value[0]` 是展示名**（历史消息列表里显示的中文名，由 `getToolNameAndDescriptionMap()` 做映射）；其余元素拼成给 LLM 的完整描述 |
| `@Tool(name = "gomoku_startGame")` | 显式指定**工具名**；不写则用**方法名** |
| `@P("说明")` | 参数说明，直接给 LLM 看。**参数描述要写全约束**（坐标范围、单位、枚举值等） |
| 末位 `InvocationParameters` | 框架注入，不占 LLM 参数表（扫描时被跳过）。用于取 userId / sessionId / agentId |
| `@ToolSecurityLevel` | 安全级别，见下 |

**安全级别**（`ToolSecurityLevel.Level`）：

| 级别 | 语义 |
| --- | --- |
| `SAFE` | 安全，免审批 |
| `PARAM_REQUIRE_APPROVAL` | 参数需审批 |
| `ALL_REQUIRE_APPROVAL` | 全部需审批 |

**命名建议**：工具名带插件前缀（如 `gomoku_startGame`、`databaseQuery_executeSelectQuery`），避免跨插件重名。

### 3.5 工具集名 / 工具名 与前端的关系

```
AgentTool.getName()  ───────────►  工具集名（ToolSetInfo.name，同时即 ToolSetInfo.pluginId 的前端路由键）
@Tool.name() 或 方法名 ─────────►  工具名（ToolInfo.name）
AgentPlugin.getId() ───────────►  pluginId（ToolSetInfo.pluginId / pluginName）
```

- 前端通过 `GET /tools/api/list` 建立 **工具名/展示名 → 工具集名** 映射（`toolOwnerSetMap`）；
- 工具执行列表**展开模式**拿到工具名，**收缩/历史模式**拿到展示名，两者都会被归一到**工具集名**，所以插件 hook 只需按工具集名过滤；
- **工具改名要注意**：历史库里存的是旧工具名，后端映射不到会回退原始名，前端此时用**别名数组**注册 hook 兜底：

```js
// canvas.js：appendDraw 是历史名称（现名 appendCanvasDraw）
PluginHook.registerToolRenderHook('afterRender', ['canvas', 'appendDraw'], handler);
```

### 3.6 配置两级化

| 级别 | 前缀 | 声明方 | 典型用途 |
| --- | --- | --- | --- |
| 插件级 | `plugin.<pluginId>.*` | `AgentPlugin.getConfigItems()` | 多工具集共享的连接信息、凭证 |
| 工具级 | `tool.<工具集名>.*` | `AgentTool.getConfigItems()` | 单个工具集的参数 |

- 前缀由**框架统一计算**，插件不要自行拼 key，改用注入的服务读取：

```java
@Autowired private IPluginConfigService pluginConfigService;   // plugin.<id>.*
@Autowired private IToolConfigService   toolConfigService;     // tool.<name>.*
```

- 配置保存会发 `ConfigChangeEvent`：`plugin.<id>.` 前缀 → 插件 `onConfigChanged()`；`tool.<name>.` 前缀 → 对应工具 `onConfigChanged()`；
- 声明了配置项才在管理页显示「配置」入口：
  - 插件配置页 `GET /plugins/config/{pluginId}`（POST 同名保存）；
  - 工具配置页 `GET /tool-config/{toolName}`（POST 同名保存）。

`ToolConfigItem` 常用写法（敏感项显式声明）：

```java
@Override
public List<ToolConfigItem> getConfigItems() {
    return List.of(
            item("driverDir", "JDBC 驱动目录", "存放 .jar 驱动的本地目录"),
            new ToolConfigItem("password", "数据库密码", "", ToolConfigItem.TYPE_PASSWORD, true));
}
```

### 3.7 invoke：通用双向调用入口

```java
@Override
public Map<String, Object> invoke(String toolRef, Map<String, Object> params) {
    Map<String, Object> r = new HashMap<>();
    r.put("success", true);
    r.put("toolRef", toolRef);
    r.put("echo", params == null ? null : params.get("text"));
    return r;
}
```

- 端点：`POST /api/plugins/{pluginId}/invoke`，body 任意 JSON 对象（可含 `toolRef` 指定工具集）→ `Map<String,Object>`，返回体即 `invoke` 返回的 Map；
- 查找顺序：**jar 动态插件优先**，其次内置 Spring Bean；
- 插件不存在 → HTTP 404 + `{success:false,message:"plugin not found: xxx"}`；插件抛异常 → HTTP 500；
- 前端调用：`PluginHook.callTool(pluginId, params)`。

### 3.8 向后端能力注入

#### (1) 下发指令到前端：IWebSocketBridgeService

```java
@Autowired private IWebSocketBridgeService webSocketBridgeService;

private boolean sendCommand(String action, String payload, String requestId,
                            InvocationParameters invocationParameters) {
    String sessionId = userIdOrSession(invocationParameters, false);
    String userId    = userIdOrSession(invocationParameters, true);
    Map<String, Object> cmd = new HashMap<>();
    cmd.put("toolName", TOOL_NAME);   // 工具栏口径沿用工具集名/pluginId
    cmd.put("action", action);
    cmd.put("payload", payload);
    cmd.put("requestId", requestId);
    return webSocketBridgeService.sendPluginCommand(userId, sessionId, JSON.toJSONString(cmd));
}
```

- **按会话隔离**：`sessionId` 非空时只推给注册了该会话的连接（前端 `plugin-hook.js` 在 `ws.onopen` 时发 `{type:"register", sessionId}`）；为空时退化为按 userId 定向或广播；
- 返回 `boolean`：`true` = 已投递到队列，`false` = 桥接异常（前端一定收不到）。**据此返回明确错误给 LLM**，不要假装成功。

#### (2) 阻塞等待前端回传：IPluginResultStore

```java
@Autowired private IPluginResultStore pluginResultStore;

@Tool(value = {"获取当前画布结果", "获取当前画布内容为图片返回给大模型，不关闭画布插件"})
public List<Content> getCanvasResult(InvocationParameters invocationParameters) {
    String requestId = UUID.randomUUID().toString();
    // ① 先注册槽位（绑定 userId，防止他人伪造回传）
    pluginResultStore.register(requestId, userIdOrSession(invocationParameters, true));
    // ② 再下发指令（顺序不能反，否则前端可能先回传）
    sendCommand("snapshot", null, requestId, invocationParameters);
    // ③ 阻塞等待（默认超时 IPluginResultStore.DEFAULT_TIMEOUT_SECONDS = 30 秒）
    String result = pluginResultStore.await(requestId, IPluginResultStore.DEFAULT_TIMEOUT_SECONDS);
    ...
}
```

前端对应：

```js
PluginHook.register('canvas', function (cmd) {
    if (cmd.action === 'snapshot') {
        PluginHook.report(cmd.requestId, canvas.toDataURL());   // string 透传
    }
});
```

- `report` 走 `POST /api/plugins/report`，body `{requestId, value}`，value 为**纯 string 透传**；
- 上报接口校验当前登录用户与注册槽位的 userId 一致；槽位不存在/已超时 → `{success:false,msg:"槽位不存在或已超时"}`。

#### (3) 从 InvocationParameters 取上下文

```java
InvocationParametersWrapper w = InvocationParametersWrapper.create(invocationParameters);
String userId    = w.getUserId();
String sessionId = w.getSessionId();
String agentId   = w.getAgentId();
```

> `@Tool` 方法里的 `invocationParameters` 可能为 `null`（HTTP 直接调用），取用前请判空。

## 4. 前端开发

### 4.1 plugin-assets.json

放在 **jar 根目录**（`src/main/resources/plugin-assets.json`）：

```json
{
  "assets": [
    { "id": "canvas-css",  "type": "css",  "path": "static/canvas.css",  "pages": ["index"] },
    { "id": "canvas-js",   "type": "js",   "path": "static/canvas.js",   "pages": ["index"], "position": "body-end" },
    { "id": "canvas-html", "type": "html", "path": "static/canvas.html", "pages": ["index"], "mount": "#plugin-slot", "mode": "append" }
  ]
}
```

| 字段 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | string | ✅ | — | **全局唯一**，前端用于去重与卸载 |
| `type` | `js`/`css`/`html` | ✅ | — | 资源类型 |
| `path` | string | ✅ | — | jar 内路径，**必须以 `static/` 开头**，不能含 `..` |
| `pages` | string[] | ✅ | — | `*` 通配所有页；`index` 精确匹配；`chat/xxx` 前缀匹配 |
| `position` | `head`/`body-start`/`body-end` | — | `body-end` | 仅 js 生效 |
| `defer` | boolean | — | `false` | 仅 js 生效 |
| `priority` | int | — | `1000` | **数值小者先注入** |
| `mount` | string | html 必填（沙箱同需） | — | 挂载选择器（如 `#plugin-slot`、`body`）；**沙箱资产取同插件第一个资产的 `mount` 作为宿主挂载点**，缺失则整个沙箱被跳过并告警 |
| `mode` | `append`/`replace`/`prepend` | — | `append` | 仅非沙箱 html 生效 |
| `sandbox` | boolean | — | `false` | **`true` 时该资产进沙箱容器**（见 §4.3），不注入宿主页面 |
| `sandboxApis` | string[] | 沙箱资产建议填 | — | 要申请的宿主能力白名单，只能取 §4.3 表里的值 |

> 约定：静态资源 URL 由后端拼成 `/api/plugins/{pluginId}/assets/{path}?v={jar 最后修改时间hex}`，响应头带 `Cache-Control: immutable`。**更新 jar 后版本号自动变化**，无需手动清缓存。

### 4.2 注入机制与时序

```
HTML 解析
 ├─ index.js            页面主逻辑（定义 handleXxx / dispatchPluginHook 等全局函数）
 ├─ plugin-hook.js      window.PluginHook 就位，并连接 /ws/plugin 下行通道
 └─ plugin-loader.js    DOMContentLoaded 后：
                          ① restoreBackground()                   ← 还原用户上次设置的会话背景
                          ② GET /api/plugins/assets?page=<body data-page>
                          ③ 资产按 priority 升序分流：
                              · 普通资产 → 串行注入 css / js / html（挂到 mount）
                              · sandbox 资产 → 按插件聚合成一个 iframe 容器统一注入
                          ④ 全部完成：派发 document 'plugin:ready'，触发 PluginLoader.onReady
 └─ window.onload（index.js）
      → loadToolIconMap() → loadInitialHistory()（渲染历史）→ connectWebSocket()
```

**由此推出的两条硬性约定：**

1. **插件 JS 一定晚于 index.js**，可以放心使用 `window.PluginHook` 等全局能力（沙箱插件除外，它拿不到宿主全局）；
2. **插件 JS 通常晚于历史消息渲染**（历史加载是异步 fetch）。凡「给已渲染 DOM 挂东西」的 hook 都必须在注册后对存量节点补挂（retrofit），且 **handler 必须幂等**。框架已内建补挂：
   - 工具渲染 hook：注册后派发 `toolrenderhooks:updated` → index.js 扫描 `.tool-call` 节点补发（`ctx.event === 'retrofit'`，`ctx.data/ctx.chat` 为 `null`）；
   - `history:node` hook：注册后派发 `pluginhooks:updated` → index.js 扫描 `.message[data-msg-id]` 补发（`ctx.retrofit === true`）；
   - `/tools/api/list` 映射就绪后也会再补挂一次（消除映射竞态）。

### 4.3 沙箱容器（纯前端插件的安全边界）

**问题**：插件 JS 若直接注入宿主页面，等于把整个页面的 DOM / localStorage / 网络能力交给第三方代码。零工具集的纯前端插件尤其危险。

**做法**：在 `plugin-assets.json` 里给资产加 `"sandbox": true`。宿主 `plugin-loader.js` 会把该插件的资产**整体装进一个 `<iframe sandbox="allow-scripts">`**：

- iframe 拿不到宿主的 DOM、cookie、localStorage（`sandbox` 不含 `allow-same-origin`）；
- 沙箱容器默认 **0×0 不可见**，由插件通过 `ui.resize` 自己展开/收起；
- 沙箱只能通过 `postMessage` 调用**宿主白名单能力**，且插件必须先在 `sandboxApis` 里声明、两边取交集后才放行；
- 同一插件的多个沙箱资产合并进**同一个 iframe**（css/html/js 按 type 拼进一份文档）。

#### 宿主能力表（`PluginLoader.sandboxApis()` 可查）

| capability | payload | 返回 | 说明 |
| --- | --- | --- | --- |
| `ui.resize` | `{width, height}` | `{width, height}` | 调整沙箱容器尺寸；宿主裁剪到 `0..480 × 0..640`，`0` 表示收起（默认态） |
| `theme.setBackground` | `{color}` | `{color\|null}` | 设置会话页背景；只接受 `#rgb` / `#rrggbb` / `rgb()` / `rgba()`，`'none'`/空表示还原；由**宿主**写入 `localStorage['hopaw.chatBackground']` |
| `theme.getBackground` | `{}` | `{color\|null}` | 查询当前会话页背景 |

#### 沙箱侧调用协议

```js
// 插件 → 宿主
window.parent.postMessage({
    __hopawPlugin: true,
    plugin: 'chat-background',   // pluginId
    id: 'req-1',                 // 自增请求号，用于对齐回执
    capability: 'ui.resize',
    payload: { width: 284, height: 272 }
}, '*');

// 宿主 → 插件（回执）
window.addEventListener('message', function (ev) {
    var msg = ev.data;
    if (!msg || msg.__hopawHost !== true || msg.id !== 'req-1') return;
    if (msg.ok) { /* msg.result */ } else { /* msg.error */ }
});

// 宿主 → 插件（广播：背景被改动时）
// { __hopawHost: true, event: 'theme:background', payload: { color } }
```

宿主侧的安全校验（写在 `plugin-loader.js` 里，插件无需关心）：

- 只认**本 iframe 的 `contentWindow`** 发来的消息，其它窗口一律丢弃；
- 能力必须在「插件声明的 `sandboxApis`」∩「宿主 `SANDBOX_HOST_APIS`」中；
- 尺寸、颜色都做规范化与上限裁剪。

#### 页面级配套

- `index.html` 的 `<body>` 需带 `data-page="index"`（`plugin-loader.js` 据此匹配 `pages`）；插槽仍在 `#plugin-slot`；
- 宿主在页面加载时自动 `restoreBackground()`，即使用户禁用了插件，已设置的背景也会还原（属于用户设置，不是插件状态）。

### 4.4 PluginHook API

| API | 签名 | 说明 |
| --- | --- | --- |
| `onCommand` | `(handler) => void` | 监听**所有**后端下发指令，`handler(cmd)` |
| `register` | `(toolName, handler) => void` | 按工具名订阅后端指令（推荐，避免多插件互相干扰） |
| `report` | `(requestId, value) => Promise` | 上报结果到后端暂存服务，`value` 为 string |
| `callTool` | `(pluginId, params) => Promise<Json>` | 调用 `POST /api/plugins/{pluginId}/invoke` |
| `registerHook` | `(name, handler) => Function` | 注册**页面生命周期 hook**（§7.2），返回注销函数 |
| `unregisterHook` | `(name, handler) => void` | 注销指定 handler |
| `hooks` | `() => Array<{name,cancelable,desc}>` | **自省**：列出全部可用 hook |
| `registerToolRenderHook` | `(phase, toolNames, handler) => void` | 注册**工具执行列表渲染 hook**（§7.1） |

推荐的插件 JS 骨架（非沙箱）：

```js
(function () {
    'use strict';
    var PLUGIN_ID = 'xxx';

    function handleCommand(cmd) {
        switch (cmd.action) {
            case 'start': openPanel(); break;
            case 'draw':  render(cmd.payload); break;
            case 'close': closePanel(); break;
        }
    }

    function init() {
        if (window.PluginHook) {
            window.PluginHook.register(PLUGIN_ID, handleCommand);
            window.PluginHook.registerHook('app:ready', onAppReady);
        }
    }

    if (document.readyState === 'loading') document.addEventListener('DOMContentLoaded', init);
    else init();
})();
```

## 5. 图标

### 命名与存放

| 类型 | `getIcon()` 返回值 | 文件存放位置（jar 内） |
| --- | --- | --- |
| 插件图标 | `xxx.svg` | `static/icons/plugins/xxx.svg` |
| 工具集图标 | `xxx-tool.svg` | `static/icons/tools/xxx-tool.svg` |
| 内置工具图标 | `xxx-tool.svg` | `hopaw-app/src/main/resources/static/icons/tools/xxx-tool.svg` |

### 解析规则（务必理解）

**插件 JAR 不在应用静态资源目录下**，浏览器直接请求 `/icons/tools/xxx.svg` 只能拿到 hopaw-app 自带的图标，插件图标走 URL **必然 404**。因此后端统一把图标**内联成 SVG 代码**下发：

1. `PluginIconResolver.resolvePluginIcon(entry, icon)`：优先读 JAR 内 `static/icons/plugins/<文件名>`，回退 `static/icons/tools/`；读不到返回**空串**（前端渲染兜底占位图标）；
2. `PluginIconResolver.resolveToolIcon(entry, icon)`：优先 `static/icons/tools/`，回退 `static/icons/plugins/`；读不到**原样返回文件名**（不引入回归）；
3. `getIcon()` 返回值以 `<svg` 开头 → 直接当代码用，不做文件查找；
4. 前端 `icon` 字段：以 `<svg` 开头 → **内联渲染**；否则视为 URL/文件名，拼 `/icons/tools/` 后用 `<img>` 加载；
5. 仓库侧（`hopaw-plugin-repo`）没有静态资源目录，故导入/扫描时**就地解包 zip → jar** 读出图标再内联（结果带内存缓存，取不到则退回文件名）。

→ **插件图标必须是 SVG 文本文件**。PNG/JPG 会被当文本读出，前端渲染成乱码。

### 图标文件建议

```svg
<svg viewBox="0 0 24 24" width="24" height="24" fill="none"
     stroke="currentColor" stroke-width="1.8" stroke-linecap="round" stroke-linejoin="round">
  <!-- 使用 currentColor 以自动适配亮/暗主题 -->
  <circle cx="12" cy="12" r="9"/>
</svg>
```

- 使用 `currentColor`，不要写死深色（暗色主题下会看不见）；
- 建议 `viewBox="0 0 24 24"`；
- 参考实现：`tools/hopaw-tool-database/src/main/resources/static/icons/plugins/database.svg`。

## 7. Hook 扩展体系

插件系统提供**两套** hook，互不干扰：

| 体系 | 目的 | 注册 API | 是否按工具过滤 |
| --- | --- | --- | --- |
| 工具执行列表渲染 hook | 定制「工具调用项」在执行列表/历史里的渲染 | `registerToolRenderHook` | ✅ 按工具集名 |
| 页面生命周期 hook | 介入消息收发、流式渲染、历史、会话、模型等页面事件 | `registerHook` | ❌ 全局 |

### 7.1 工具执行列表渲染 hook

```js
PluginHook.registerToolRenderHook(phase, toolNames, handler);
```

| phase | 触发范围 | 返回值语义 |
| --- | --- | --- |
| `beforeRender` | ★ 通用：**任何**工具项渲染前（实时 + 历史） | 返回 `false` → 跳过默认渲染，插件接管 |
| `afterRender` | ★ 通用：**任何**工具项渲染完成后 | 忽略 |
| `beforeStaticRender` | 精细点：**仅历史列表**渲染前 | 返回 `false` → 只保留空容器 |
| `afterStaticRender` | 精细点：**仅历史列表**渲染完成后 | 忽略 |

> `beforeRender` / `afterRender` 会**同时**在静态渲染时触发，只注册这两个即可覆盖全部工具项。

`toolNames` 过滤：字符串 / 字符串数组 / `null`。命中 `ctx.toolName` **或** `ctx.toolSetName` 即调用；数组用于声明**历史别名**。

`ctx` 字段：

| 字段 | 说明 |
| --- | --- |
| `phase` | `'live'`（实时） / `'static'`（历史） |
| `event` | 实时工具状态（`preparing`/`started`/`running`/`approval`/`rejected`/`executed`）；补挂时为 `'retrofit'` |
| `status` | 同 `event` |
| `toolCallId` / `toolName` / `toolSetName` | 标识 |
| `data` / `chat` | 原始数据；**补挂时为 `null`** |
| `element` | 工具项根 DOM（`.tool-call`） |
| `header` / `body` | 头部 / 内容区 DOM，after 系列可直接追加按钮 |

**示例（画布插件的「打开插槽」按钮）**：

```js
if (window.PluginHook && window.PluginHook.registerToolRenderHook) {
    window.PluginHook.registerToolRenderHook('afterRender', ['canvas', 'appendDraw'], function (ctx) {
        var header = ctx.header || (ctx.element && ctx.element.querySelector('.tool-call-header'));
        if (!header) return;
        if (header.querySelector('.tool-call-slot-btn')) return;   // 幂等：补挂会重复触发
        var btn = document.createElement('button');
        btn.type = 'button';
        btn.className = 'tool-call-slot-btn';
        btn.title = '打开画布插槽';
        btn.innerHTML = '<svg viewBox="0 0 24 24" width="12" height="12" fill="none" stroke="currentColor" stroke-width="2"><rect x="3" y="4" width="18" height="16" rx="2"/></svg>';
        btn.onclick = function (e) { e.stopPropagation(); window.openCanvasSlot(); };
        header.appendChild(btn);
    });
}
```

### 7.2 页面生命周期 hook

```js
var off = PluginHook.registerHook(name, handler);   // 返回注销函数
PluginHook.unregisterHook(name, handler);
PluginHook.hooks();                                 // 控制台自省全部可用 hook
```

**通用约定**

- 同一 hook 可注册多个 handler，按**注册顺序**调用；后注册的也能收到**补挂**（`ctx.retrofit === true`）；
- **cancelable = true** 的 hook（仅 3 个：`message:before-send`、`ws:message`、`history:before-node`）：任一 handler 返回 `false` → 整体取消；
- 非 cancelable hook 的返回值被忽略；
- 单个 handler 抛异常会被捕获并打日志，**不影响**其它 handler；
- 注册未知名 hook 会 `console.warn` 提示（防拼写错误），并返回空操作注销函数；
- **handler 必须幂等**：`stream:*` 每次片段都触发；带补挂的 hook 会对存量 DOM 再触发一次；
- **高频 hook**（`stream:text` / `stream:thinking`）请保持 handler 轻量，必要时自行节流。

**典型示例**

```js
// 1) 拦截发送
PluginHook.registerHook('message:before-send', function (ctx) {
    if (ctx.message === 'forbidden') { alert('该消息不允许发送'); return false; }
    ctx.payload.message = '[前缀] ' + ctx.payload.message;
});

// 2) 给每条历史消息追加「引用」按钮（注意幂等）
PluginHook.registerHook('history:node', function (ctx) {
    var el = ctx.element;
    if (!el || el.querySelector('.my-quote-btn')) return;
    var b = document.createElement('button');
    b.className = 'my-quote-btn';
    b.textContent = '引用';
    b.onclick = function () { /* ... */ };
    el.appendChild(b);
});

// 3) 流式文本渲染后二次加工
PluginHook.registerHook('stream:text', function (ctx) {
    if (!ctx.contentEl || ctx.status !== 'done') return;
    highlight(ctx.contentEl);
});

// 4) 接管自定义下行消息类型
PluginHook.registerHook('ws:message', function (ctx) {
    if (ctx.type !== 'my-custom-event') return true;   // 不关心 → 放行
    renderMyEvent(ctx.data);
    return false;                                      // 已处理 → 阻止内置分发
});

// 5) 统计到达后追加自定义指标
PluginHook.registerHook('stats:task', function (ctx) {
    if (!ctx.statsEl || ctx.statsEl.querySelector('.my-metric')) return;
    var s = document.createElement('span');
    s.className = 'agent-turn-stats-item my-metric';
    s.textContent = '自定义 ' + ctx.data.toolCallCount;
    ctx.statsEl.appendChild(s);
});
```

完整 hook 清单见 [附录](#12-附录)，或运行时 `PluginHook.hooks()`。

沙箱内脚本（`chat-background.js`）核心片段：

```js
var seq = 0, pending = {};

/** 经 postMessage 调用宿主白名单能力 */
function call(capability, payload) {
    return new Promise(function (resolve) {
        var id = 'cb-' + (++seq);
        pending[id] = resolve;
        window.parent.postMessage({
            __hopawPlugin: true, plugin: 'chat-background',
            id: id, capability: capability, payload: payload || {}
        }, '*');
    });
}

window.addEventListener('message', function (ev) {
    var msg = ev.data;
    if (!msg || msg.__hopawHost !== true) return;
    if (msg.event === 'theme:background') { syncSwatch(msg.payload && msg.payload.color); return; }
    var done = pending[msg.id];
    if (!done) return;
    delete pending[msg.id];
    done(msg.ok ? msg.result : null);
});

var COLLAPSED = { width: 48,  height: 48  };   // 收起：只露一个圆钮
var EXPANDED  = { width: 284, height: 272 };   // 展开：配色面板

document.getElementById('cbFab').onclick = function () {
    call('ui.resize', EXPANDED).then(function () {
        document.getElementById('cbPanel').classList.add('open');
    });
};

function apply(color) {
    call('theme.setBackground', { color: color });
}

// 启动：先把自己收起来，再问宿主当前背景色
call('ui.resize', COLLAPSED).then(function () { return call('theme.getBackground'); })
    .then(function (r) { syncSwatch(r && r.color); });
```

## 10. 调试与排错

| 场景 | 做法 |
| --- | --- |
| 查可用 hook | 控制台：`PluginHook.hooks()` |
| 查 hook 是否注册成功 | `PluginHook.dispatchHook('xxx', {})`，看 handler 是否被调用 |
| 查沙箱可用能力 | 控制台：`PluginLoader.sandboxApis()` |
| 查工具集名映射 | `window.toolOwnerSetMap`（工具名/展示名 → 工具集名） |
| 查工具集清单与图标 | 浏览器访问 `/tools/api/list`（`icon` 以 `<svg` 开头即内联成功） |
| 查插件清单 | 浏览器访问 `/plugins/api/list` |
| 前端改了不生效 | `Ctrl+F5` 强刷；`index.html` 中 `index.js` / `plugin-hook.js` / `plugin-loader.js` 带 `(v=yyyyMMddx)` 版本号，改动后需同步升级 |
| 后端静态资源改了不生效 | **exec jar 被运行中的 JVM 锁住，必须先停应用**再替换 jar（`netstat -ano -p TCP | findstr :8080` 找 PID → `taskkill /PID <pid> /F`），然后重启 |
| 插件 jar 更新 | ① 停应用 → 替换 `plugins/*.jar` → 启动；② 不停应用，走 `POST /plugins/api/local-install`（或让 LLM 用 `pluginTool`）热装 |
| 插件的静态资源不生效 | 资源 URL 带 `?v=<jar lastModified hex>`，重装后自动变化；确认 `plugin-assets.json` 的 `path` 确实以 `static/` 开头 |
| 看插件是否加载 | 日志搜 `plugin.asyncInit` 前后的注册记录；被拒绝时会有"未提供 AgentPlugin 实现"或"同 pluginId 已存在"的 warn |
| 沙箱插件界面不出现 | 容器默认 0×0，插件必须先自己 `ui.resize` 展开；确认 `sandbox:true` 且 `sandboxApis` 声明了要用的能力 |
| 看下发指令是否投递 | 插件日志：`send command action=... delivered=true/false` |
| 全量打包 | `mvn clean package -DskipTests`（22 模块 BUILD SUCCESS，含 `hopaw-plugin-repo`）。只验证主程序可用 `mvn package -DskipTests -pl hopaw-app -am` |

**构建注意**

- 构建 exec jar 前建议先停应用，否则 `clean` 无法删除被占用的 jar；
- 只改静态资源也可用 zip 直接替换 jar 内条目，同样需先停应用；
- 编译报「找不到符号 `Autowired`」→ 插件 `pom.xml` 缺 `spring-beans`（`provided`）。

## 11. 常见问题

**Q1：`getSlotOpener()` / `getXxx()` 之类的字段是不是要加在 AgentTool 上？**
不加。插件的 UI 定制请走 **hook 体系**（§7），主程序零定制。

**Q2：我写的插件 JAR 加载不了？**
两个硬性原因：① JAR 内**没有 `AgentPlugin` 实现类**（纯前端插件也必须提供一个 `getTools()` 返回空列表的插件类）；② **同 pluginId 已存在**——升级请走覆盖安装，不要放两个同 id 的 JAR。

**Q3：hook 注册了但没反应？**
按顺序排查：
1. 名称是否拼错 → 控制台会有 `[plugin-hook] 未知 hook 名称：xxx`；
2. 是否在 `window.PluginHook` 就绪后才调用（非沙箱插件 JS 一定晚于 plugin-hook.js）；
3. 是针对**已渲染**内容吗 → 需要补挂的 hook 只有 `history:node` 和工具渲染 hook；错过时机可用 `document.addEventListener('plugin:ready', ...)` 自行扫 DOM；
4. 是否被前一个 handler 返回 `false` 取消了（仅 cancelable hook，且整体取消）。

**Q4：按钮加了两次 / 内容重复渲染？**
hook 会对存量 DOM 补挂，且 `stream:*` 每次片段都触发。加 DOM 前必须先判重（如 `if (el.querySelector('.my-btn')) return;`）。

**Q5：插件图标显示不出来（乱码或空白）？**
① 图标必须是 **SVG 文本**，且放在 `static/icons/plugins/`（插件）或 `static/icons/tools/`（工具集）；② `getIcon()` 不能留空或等于默认值 `agent-tool.svg`（插件图标解析不到时会返回空串触发占位图标）；③ 返回 PNG 会被当文本读出而乱码。

**Q6：容器里的插件 JS 报 `document is not defined` / 改不动页面？**
你的资产被标了 `sandbox: true`，运行在 `<iframe sandbox="allow-scripts">` 里，**拿不到宿主 DOM**。这是设计如此。要么改用宿主白名单能力（§4.3），要么去掉 `sandbox` 走普通注入（此时插件 JS 与页面同权，请自行确保可信）。

**Q7：工具改名后历史记录里的旧项匹配不到 hook / 显示空名？**
后端对映射不到的旧工具名会**回退原始名**；前端注册 hook 时用**数组**写出历史别名即可命中，例如 `['canvas', 'appendDraw']`。

**Q8：多插件互相收到对方的指令？**
用 `PluginHook.register(toolName, handler)` 按工具名订阅（而不是 `onCommand`）。后端侧指令已按 `sessionId` 做会话隔离。

**Q9：前端没收到后端的插件指令？**
1. 前端是否连上 `/ws/plugin` 且注册了当前会话；
2. 后端 `sendPluginCommand` 返回值是否为 `true`；
3. `sessionId` 是否与浏览器打开的会话一致；
4. 指令的 `toolName` 是否与前端 `register` 的一致。

**Q10：@Tool 方法一直阻塞到超时？**
前端必须回传 `PluginHook.report(requestId, value)`；用户中途关闭插槽也要回传（哪怕空串）。建议 timeout 用 `IPluginResultStore.DEFAULT_TIMEOUT_SECONDS`。

**Q11：插件配置读不到？**
插件用 `IPluginConfigService`（`plugin.<id>.*`），工具用 `IToolConfigService`（`tool.<name>.*`），**不要自己拼 key**。前缀由框架统一计算，`AgentTool.getConfigPrefix()` 只是默认实现、无需覆盖。
