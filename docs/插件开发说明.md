## 1. 整体架构

一个插件 = **一个 jar**，jar 内同时包含：

| 部分 | 载体 | 作用 |
| --- | --- | --- |
| 后端工具 | `AgentTool` 实现类（jar 根 class） | 向 LLM 暴露 `@Tool` 方法 |
| 前端资源清单 | `plugin-assets.json`（jar 根） | 声明 js/css/html 注入到哪些页面 |
| 前端资源 | `static/**.js/css/html` | 浏览器侧交互逻辑 |
| 图标 | `static/icons/tools/*.svg` | 工具集图标 |

数据流（三通道）：

```
                          ┌──────────── ① 工具调用（LLM → 后端 @Tool 方法）
用户 / LLM ──► AgentExecutor ──► AgentTool.@Tool(...)
                                      │
                                      │ ② 下发前端指令
                                      ▼
                     IWebSocketBridgeService.sendPluginCommand(userId, sessionId, payload)
                                      │  Spring Event → Artemis 队列 ws.plugin.cmd
                                      ▼
                         PluginWebSocketHandler → /ws/plugin（按 sessionId 定向）
                                      ▼
                         plugin-hook.js（window.PluginHook）→ 分发到插件 JS

   插件 JS 完成后 ──③ 回传结果──► POST /api/plugins/report ──► IPluginResultStore.complete()
                                                              │
       后端 @Tool 阻塞在 IPluginResultStore.await() 被唤醒 ◄────┘
```

另有 **invoke 双向通道**：`POST /api/plugins/{toolName}/invoke` → `AgentTool.invoke(Map)`，前端可直接按需向插件后端要数据，无需走 @Tool / LLM。

## 2. 插件工程骨架

以 `tools/hopaw-tool-canvas` 为模板：

```
tools/hopaw-tool-xxx/
├── pom.xml
└── src/main/
    ├── java/com/agent/hopaw/tool/xxx/
    │   └── XxxTool.java                    # implements AgentTool
    └── resources/
        ├── plugin-assets.json              # 前端资源清单（必须在 jar 根）
        └── static/
            ├── xxx.js                      # 前端逻辑（向 PluginHook 注册）
            ├── xxx.css
            ├── xxx.html                    # 插槽 DOM（挂到 #plugin-slot）
            └── icons/tools/xxx-tool.svg     # 工具集图标
```

### pom.xml 关键点

```xml
<parent>
    <groupId>com.hopaw.agent</groupId>
    <artifactId>hopaw-agent</artifactId>
    <version>1.0.0</version>
    <relativePath>../../pom.xml</relativePath>
</parent>
<packaging>jar</packaging>
<properties>
    <!-- 不安装到本地仓库，避免污染主工程依赖 -->
    <maven.install.skip>true</maven.install.skip>
</properties>
```

依赖（**全部 `provided`**，运行期由主工程提供）：

| 依赖 | 用途 |
| --- | --- |
| `com.hopaw.agent:hopaw-contract` | `AgentTool` / `IWebSocketBridgeService` / `IPluginResultStore` 等契约 |
| `dev.langchain4j:langchain4j` | `@Tool` / `@P` / `InvocationParameters` |
| `org.springframework:spring-beans` | `@Autowired`（插件实例会被 `autowireBean` 注入） |
| `com.alibaba.fastjson2:fastjson2` | JSON 序列化（下发指令 payload） |
| `org.slf4j:slf4j-api` | 日志 |

构建插件：

- `maven-shade-plugin`：打 FAT jar，**排除** `dev.langchain4j:*` 与 `org.slf4j:*`（主工程已提供），并剔除 `META-INF/*.SF|DSA|RSA`（避免签名校验失败）。
- `maven-antrun-plugin`：`package` 阶段把产物复制到 `../../plugins/`。

> **只构建单个插件**：`mvn package -DskipTests -pl tools/hopaw-tool-xxx -am`
> （`-am` 会一并构建它的父 POM 依赖链）

### 加载机制

应用启动、Spring 容器就绪后，`JarPluginLoader`（`ApplicationReadyEvent`）：

1. 扫描 `${agent.plugin.dir:plugins}/*.jar`，**按文件名排序**加载（插件间若有依赖，被依赖方文件名必须排前）；
2. `PluginClassLoader.scanAgentToolClasses()` 找出 jar 内所有 `AgentTool` 实现类；
3. 逐个 `newInstance()` → `beanFactory.autowireBean(tool)`（所以插件里可以 `@Autowired`）→ `asyncInit()`；
4. 注册进 `DynamicToolRegistry`；同时解析 `plugin-assets.json` 缓存资源清单。

### 插件的安装 / 升级 / 卸载（无需重启）

| 端点 | 方法 | 说明 |
| --- | --- | --- |
| `/tools/api/install-upgrade` | POST | 安装或升级插件（zip 包：包含 `.json` 清单 + `.jar`） |
| `/tools/api/local-install` | POST | 从本地文件（.jar / zip）直接安装 |
| `/tools/api/unload` | POST | 卸载指定插件（会调用各工具的 `destroy()` 并关闭 classloader，释放 jar 文件句柄） |
| `/tools/api/export/{toolName}/{toolVersion}` | GET | 导出插件为 zip 包 |
| `/tools/plugin-store` | GET | 插件商店页面（浏览远端仓库插件） |

后端服务接口：`IAgentToolService`（`installOrUpgradePlugin` / `installPluginFromJarFile` / `installPluginFromBytes` / `exportPlugin` / `unloadPlugin`）。

另外内置了一个 **`pluginTool`** 工具集，让 LLM 也能装插件：

- `installPluginToolFromLocal` —— 从本地 zip 插件包安装；
- `installPluginFromLocalJar` —— 从本地 `.jar` 直接安装。

## 3. 后端开发

### 3.1 AgentTool 接口

```java
public interface AgentTool {
    String getName();                 // 工具集名（如 canvas / gomoku）
    String getDescription();          // 工具集描述
    default String getIcon()          { return "agent-tool.svg"; }
    default String getVersion()       { return "1.0.0"; }
    default String getAuthor()        { return "Agent Tool"; }
    default String getUrl()           { return "https://gitee.com/hgflydream/hopaw-agent"; }
    default String getKeyword()       { return ""; }          // 关键词，便于检索匹配
    default void asyncInit()          { }                     // 异步初始化
    default void destroy()            { }                     // 卸载清理
    default List<ToolConfigItem> getConfigItems() { return List.of(); }   // 配置项定义
    default String getConfigPrefix()  { return "tool." + getName() + "."; }
    default void onConfigChanged()    { }                     // 配置保存后回调
    default Map<String, Object> invoke(Map<String, Object> params) { /* 默认不支持 */ }
}
```

`getName()` 即 **工具集名**，前端 hook 过滤、图标映射、工具执行列表分组都以它为准。

### 3.2 @Tool 方法规范

```java
@ToolSecurityLevel(ToolSecurityLevel.Level.SAFE)
@Tool(value = {"开始画布绘制", "在浏览器前端收缩会话区并新建一个并排的实时画布，返回确认信息"})
public String drawCanvas(
        @P("绘制说明，例如要绘制的内容主题") String description,
        InvocationParameters invocationParameters) {
    ...
}
```

| 写法 | 说明 |
| --- | --- |
| `@Tool(value = {...})` | **`value[0]` 是展示名**（历史消息列表里显示的中文名，由后端 `getToolNameAndDescriptionMap()` 做映射）；其余元素拼成给 LLM 的完整描述 |
| `@Tool(name = "gomoku_startGame")` | 显式指定**工具名**；不写则用**方法名** |
| `@P("说明")` | 参数说明，直接给 LLM 看。**参数描述要写全约束**（坐标范围、单位、枚举值等） |
| 末位 `InvocationParameters` | 框架注入，不占 LLM 参数表（扫描时被跳过）。用于取 userId / sessionId / agentId |
| `@ToolSecurityLevel` | 安全级别，见下 |

**安全级别**（`ToolSecurityLevel.Level`）：

| 级别 | 语义 |
| --- | --- |
| `SAFE` | 安全，免审批 |
| `PARAM_REQUIRE_APPROVAL` | 参数需审批 |
| `ALL_REQUIRE_APPROVAL` | 全部需审批 |

**命名建议**：工具名最好带工具集前缀（如 `gomoku_startGame`、`drawCanvas`），避免不同插件工具重名。

### 3.3 工具集名 / 工具名 与前端的关系

```
AgentTool.getName()  ───────────►  工具集名（ToolSetInfo.name）
@Tool.name() 或 方法名 ─────────►  工具名（ToolInfo.name）
```

- 前端通过 `GET /tools/api/list` 建立 **工具名/展示名 → 工具集名** 映射（`toolOwnerSetMap`）；
- 工具执行列表里**展开模式**拿到的是工具名（`drawCanvas`），**收缩/历史模式**拿到的是展示名（"开始画布绘制"），两者都会被归一到**工具集名**，所以插件 hook 只需要按工具集名过滤；
- **工具改名要注意**：历史库里存的是旧工具名，改名后后端映射不到会回退原始名（`getOrDefault`），前端此时可用**别名数组**注册 hook 兜底。示例：

```js
// canvas.js：appendDraw 是历史名称（现名 appendCanvasDraw）
PluginHook.registerToolRenderHook('afterRender', ['canvas', 'appendDraw'], handler);
```

### 3.4 invoke：通用双向调用入口

需要前端主动向后端插件要数据/发数据时，覆盖 `invoke`：

```java
@Override
public Map<String, Object> invoke(Map<String, Object> params) {
    Map<String, Object> r = new HashMap<>();
    r.put("success", true);
    r.put("echo", params.get("text"));
    return r;
}
```

- 端点：`POST /api/plugins/{toolName}/invoke`，请求体任意 JSON 对象 → `Map<String,Object>`，返回体即 `invoke` 返回的 Map；
- 查找顺序：**jar 动态插件优先**，其次内置 Spring Bean；
- 工具不存在 → HTTP 404 + `{success:false,message:"tool not found: xxx"}`；插件抛异常 → HTTP 500；
- 前端调用：`PluginHook.callTool(toolName, params)`。

### 3.5 配置项

```java
@Override
public List<ToolConfigItem> getConfigItems() {
    return List.of(/* option / text / number / switch 等类型的配置项 */);
}

@Override
public void onConfigChanged() {
    // 配置保存后重建内部对象（如 HttpClient、连接池）
}
```

- 配置键前缀：`getConfigPrefix()`，默认 `tool.<工具集名>.`；
- 配置保存会发 `ConfigChangeEvent`，`AgentToolService` 按前缀匹配后调用对应插件的 `onConfigChanged()`；
- 声明了配置项的工具集，前端会在工具执行列表项上显示「配置」按钮（`ToolSetInfo.hasConfigItems`）。

### 3.6 向后端能力注入

#### (1) 下发指令到前端：IWebSocketBridgeService

```java
@Autowired
private IWebSocketBridgeService webSocketBridgeService;

private boolean sendCommand(String action, String payload, String requestId,
                            InvocationParameters invocationParameters) {
    String sessionId = userIdOrSession(invocationParameters, false);
    String userId     = userIdOrSession(invocationParameters, true);
    Map<String, Object> cmd = new HashMap<>();
    cmd.put("toolName", TOOL_NAME);
    cmd.put("action", action);
    cmd.put("payload", payload);
    cmd.put("requestId", requestId);
    return webSocketBridgeService.sendPluginCommand(userId, sessionId, JSON.toJSONString(cmd));
}
```

- **按会话隔离**：`sessionId` 非空时，指令只推给**注册了该会话**的前端连接（前端 `plugin-hook.js` 在 `ws.onopen` 时发送 `{type:"register", sessionId}`）；为空时退化为按 userId 定向或广播；
- 返回 `boolean`：`true` = 已成功投递到队列，`false` = 桥接异常（前端一定收不到）。**建议据此返回明确的错误信息给 LLM**，而不是假装成功；
- 也有其他通道常量：`QUEUE_TOKEN_USAGE` / `QUEUE_AGENT_MESSAGE` / `QUEUE_GLOBAL_NOTICE` / `QUEUE_AVATAR_EVENT` / `QUEUE_PLUGIN`。

#### (2) 阻塞等待前端回传：IPluginResultStore

```java
@Autowired
private IPluginResultStore pluginResultStore;

@Tool(value = {"获取当前画布结果", "获取当前画布内容为图片返回给大模型，不关闭画布插件"})
public List<Content> getCanvasResult(InvocationParameters invocationParameters) {
    String requestId = UUID.randomUUID().toString();
    // ① 先注册槽位（绑定 userId，防止他人伪造回传）
    pluginResultStore.register(requestId, userIdOrSession(invocationParameters, true));
    // ② 再下发指令（顺序不能反，否则前端可能先回传）
    sendCommand("snapshot", null, requestId, invocationParameters);
    // ③ 阻塞等待（默认超时 IPluginResultStore.DEFAULT_TIMEOUT_SECONDS = 30 秒）
    String result = pluginResultStore.await(requestId, IPluginResultStore.DEFAULT_TIMEOUT_SECONDS);
    if (result == null) {
        return List.of(new TextContent("错误: 获取结果超时，可能前端页面未打开。"));
    }
    ...
}
```

前端侧对应：

```js
PluginHook.register('canvas', function (cmd) {
    if (cmd.action === 'snapshot') {
        PluginHook.report(cmd.requestId, canvas.toDataURL());   // string 透传
    }
});
```

- `report` 走 `POST /api/plugins/report`，body `{requestId, value}`，value 为**纯 string 透传**，语义由插件自定义（base64、JSON 字符串、坐标串都行）；
- 上报接口会校验当前登录用户与注册槽位时的 userId 一致；
- 槽位不存在/已超时 → `{success:false,msg:"槽位不存在或已超时"}`。

#### (3) 从 InvocationParameters 取上下文

```java
InvocationParametersWrapper w = InvocationParametersWrapper.create(invocationParameters);
String userId    = w.getUserId();
String sessionId = w.getSessionId();
String agentId   = w.getAgentId();
```

> `@Tool` 方法里的 `invocationParameters` 可能为 `null`（如通过 HTTP 直接调用），取用前请判空。

## 4. 前端开发

### 4.1 plugin-assets.json

放在 **jar 根目录**（`src/main/resources/plugin-assets.json`）：

```json
{
  "assets": [
    { "id": "canvas-css",  "type": "css",  "path": "static/canvas.css",  "pages": ["index"] },
    { "id": "canvas-js",   "type": "js",   "path": "static/canvas.js",   "pages": ["index"], "position": "body-end" },
    { "id": "canvas-html", "type": "html", "path": "static/canvas.html", "pages": ["index"], "mount": "#plugin-slot", "mode": "append" }
  ]
}
```

| 字段 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | string | ✅ | — | **全局唯一**，前端用于去重与卸载（`PluginLoader.unload`） |
| `type` | `js`/`css`/`html` | ✅ | — | 资源类型 |
| `path` | string | ✅ | — | jar 内路径，**必须以 `static/` 开头**，不能含 `..`（否则被跳过并告警） |
| `pages` | string[] | ✅ | — | 页面标识：`*` 通配所有页；`index` 精确匹配；`chat/xxx` 前缀匹配 `chat/` |
| `position` | `head`/`body-start`/`body-end` | — | `body-end` | 仅 js 生效 |
| `defer` | boolean | — | `false` | 仅 js 生效 |
| `priority` | int | — | `1000` | **数值小者先注入**，用于控制插件间依赖顺序 |
| `mount` | string | html 必填 | — | 挂载选择器（如 `#plugin-slot`） |
| `mode` | `append`/`replace`/`prepend` | — | `append` | 仅 html 生效 |

> 约定：静态资源 URL 由后端拼成 `/api/plugins/{jar文件名}/assets/{path}?v={jar最后修改时间hex}`，响应头带 `Cache-Control: immutable`。**更新 jar 后版本号自动变化**，无需手动清缓存。

### 4.2 注入机制与时序（重要）

```
HTML 解析
 ├─ index.js            页面主逻辑（定义 handleXxx / dispatchPluginHook 等全局函数）
 ├─ plugin-hook.js      window.PluginHook 就位，并连接 /ws/plugin 下行通道
 └─ plugin-loader.js    DOMContentLoaded 后：
                          GET /api/plugins/assets?page=<body data-page>
                          → 按 priority 升序 **串行** 注入 css / js / html
                          → 全部完成：派发 document 'plugin:ready'，并触发 PluginLoader.onReady 回调
 └─ window.onload（index.js）
      → loadToolIconMap()  → loadInitialHistory()（渲染历史）→ connectWebSocket()
```

**由此推出的两条硬性约定：**

1. **插件 JS 一定晚于 index.js**，可以放心使用 `window.PluginHook`、`window.openXxxSlot` 等全局能力；
2. **插件 JS 通常晚于历史消息渲染**（历史加载是异步 fetch）。凡是「给已渲染 DOM 挂东西」的 hook，都必须在注册后对存量节点做补挂（retrofit），并且 **handler 必须幂等**。框架已内建补挂：

   - 工具渲染 hook：注册后派发 `toolrenderhooks:updated` → index.js 扫描所有 `.tool-call` 节点补发 after hook（`ctx.event === 'retrofit'`，`ctx.data/ctx.chat` 为 `null`）；
   - `history:node` hook：注册后派发 `pluginhooks:updated` → index.js 扫描所有 `.message[data-msg-id]` 补发（`ctx.retrofit === true`，`ctx.chat` 为 `null`）；
   - `/tools/api/list` 映射就绪后也会再补挂一次（消除「工具集名映射还没到」的竞态）。

### 4.3 PluginHook API

| API | 签名 | 说明 |
| --- | --- | --- |
| `onCommand` | `(handler) => void` | 监听**所有**后端下发指令，`handler(cmd)` |
| `register` | `(toolName, handler) => void` | 按工具名订阅后端指令（推荐，避免多插件互相干扰） |
| `report` | `(requestId, value) => Promise` | 上报结果到后端暂存服务，`value` 为 string |
| `callTool` | `(toolName, params) => Promise<Json>` | 调用 `POST /api/plugins/{toolName}/invoke` |
| `registerHook` | `(name, handler) => Function` | 注册**页面生命周期 hook**（见 §7.2），返回注销函数 |
| `unregisterHook` | `(name, handler) => void` | 注销指定 handler |
| `hooks` | `() => Array<{name,cancelable,desc}>` | **自省**：列出全部可用 hook（控制台可直接查） |
| `registerToolRenderHook` | `(phase, toolNames, handler) => void` | 注册**工具执行列表渲染 hook**（见 §7.1） |

推荐的插件 JS 骨架：

```js
(function () {
    'use strict';
    var TOOL_NAME = 'xxx';

    function handleCommand(cmd) {
        switch (cmd.action) {
            case 'start':  openPanel(); break;
            case 'draw':   render(cmd.payload); break;
            case 'close':  closePanel(); break;
        }
    }

    function init() {
        if (window.PluginHook) {
            window.PluginHook.register(TOOL_NAME, handleCommand);   // 只订阅自己的指令
            window.PluginHook.registerHook('app:ready', onAppReady); // 页面就绪后做一次性初始化
        }
    }

    if (document.readyState === 'loading') document.addEventListener('DOMContentLoaded', init);
    else init();
})();
```

## 5. 图标

### 命名与存放

| 类型 | `getIcon()` 返回值 | 文件存放位置 |
| --- | --- | --- |
| 内置工具 | `xxx-tool.svg` | `hopaw-app/src/main/resources/static/icons/tools/xxx-tool.svg` |
| **插件工具** | `xxx-tool.svg` | 插件 jar 内 `static/icons/tools/xxx-tool.svg` |

### 解析规则（务必理解）

1. 后端扫描工具集时，若 `getIcon()` **不等于默认值 `agent-tool.svg`**，会从 jar 读取
   `static/icons/tools/<getIcon()>` 的**文本内容**塞进 `ToolSetInfo.icon`：
   ```java
   if (!AgentTool.DEFAULT_ICON.equals(toolSetInfo.getIcon())) {
       toolSetInfo.setIcon(entry.getCachedResource("static/icons/tools/" + tool.getIcon()));
   }
   ```
   → **插件图标必须是 SVG 文本文件**。PNG/JPG 会被当作文本读出，前端渲染成乱码。
2. 前端 `JSON` 里 `icon` 字段：以 `<svg` 开头 → **内联渲染**（`innerHTML`）；否则视为 URL/文件名，拼 `/icons/tools/` 前缀后用 `<img>` 加载。
3. `getIcon()` 留空/等于默认值 → 前端回退成 🔧。

### 图标文件建议

```svg
<svg viewBox="0 0 24 24" width="24" height="24" fill="none"
     stroke="currentColor" stroke-width="1.8" stroke-linecap="round" stroke-linejoin="round">
```

## 6. 事件通知

### 6.1 前端 DOM 事件

> ⚠️ 下表是 **DOM 事件**，用 `document.addEventListener`（或 `PluginLoader.onReady`）监听，
> **不是** `PluginHook.registerHook` 的 hook 名称，不要混用。

| 事件名 | 派发者 | detail | 用途 |
| --- | --- | --- | --- |
| `plugin:ready` | `plugin-loader.js` | `{assets: [id...]}` | **所有插件资源注入完成**。做跨插件协作、DOM 扫描兜底 |
| `plugin:mounted` | `plugin-loader.js` | `{id, plugin}` | 某个 html 资源挂载完成（冒泡自挂载容器） |
| `toolrenderhooks:updated` | `plugin-hook.js` | — | 工具渲染 hook 有新增 → 触发工具项存量补挂 |
| `pluginhooks:updated` | `plugin-hook.js` | `{name}` | 通用 hook 有新增 → 触发支持补挂的 hook（`history:node`） |

两种用法：

```js
// 方式一：DOM 事件
document.addEventListener('plugin:ready', function (e) {
    console.log('已注入插件资源：', e.detail.assets);
});

// 方式二：loader 回调（等价，更简洁）
PluginLoader.onReady(function () { /* ... */ });
```

### 6.2 后端 → 前端（插件指令）

| 项 | 值 |
| --- | --- |
| 端点 | `ws://<host>/ws/plugin`（由 `plugin-hook.js` 自动连接，断线 3 秒重连） |
| 会话注册 | 连接建立后前端自动发送 `{type:"register", sessionId: window.currentSessionId}` |
| 消息体 | `{toolName, action, payload, requestId}`（插件自定义，建议保持此结构） |
| 分发 | `PluginHook.register(toolName, h)` 只收自己的；`PluginHook.onCommand(h)` 收全部 |
| 隔离 | 后端按 `sessionId` 定向下发，A 会话的指令不会推到 B 会话的浏览器 |

## 7. Hook 扩展体系

插件系统提供**两套** hook，互不干扰：

| 体系 | 目的 | 注册 API | 是否按工具过滤 |
| --- | --- | --- | --- |
| 工具执行列表渲染 hook | 定制「工具调用项」在右侧执行列表/历史里的渲染 | `registerToolRenderHook` | ✅ 按工具集名 |
| 页面生命周期 hook | 介入消息收发、流式渲染、历史、会话、模型等页面事件 | `registerHook` | ❌ 全局 |

### 7.1 工具执行列表渲染 hook

```js
PluginHook.registerToolRenderHook(phase, toolNames, handler);
```

`phase` 取值与语义：

| phase | 触发范围 | 返回值语义 |
| --- | --- | --- |
| `beforeRender` | ★ 通用：**任何**工具项渲染前（实时 + 历史） | 返回 `false` → 跳过默认渲染，插件接管 |
| `afterRender` | ★ 通用：**任何**工具项渲染完成后 | 忽略 |
| `beforeStaticRender` | 精细点：**仅历史列表**渲染前 | 返回 `false` → 只保留空容器 |
| `afterStaticRender` | 精细点：**仅历史列表**渲染完成后 | 忽略 |

> 语义收敛说明：`beforeRender` / `afterRender` 会**同时**在静态渲染时触发，因此**只注册这两个就能覆盖全部工具项**；`*StaticRender` 是给「只想处理历史项」的场景用的额外精细点。

`toolNames` 过滤：字符串 / 字符串数组 / `null`。命中 `ctx.toolName` **或** `ctx.toolSetName` 即调用；数组用于声明**历史别名**（工具改名后旧记录仍能命中）。

`ctx` 字段：

| 字段 | 说明 |
| --- | --- |
| `phase` | `'live'`（实时） / `'static'`（历史） |
| `event` | 实时：工具状态（`preparing`/`started`/`running`/`approval`/`rejected`/`executed`）；补挂时为 `'retrofit'` |
| `status` | 同 `event`（便于统一处理） |
| `toolCallId` / `toolName` / `toolSetName` | 标识 |
| `data` / `chat` | 原始数据（实时 / 历史）；**补挂时为 `null`** |
| `element` | 工具项根 DOM（`.tool-call`） |
| `header` / `body` | 头部 / 内容区 DOM，after 系列可直接往里追加按钮 |

**示例（画布插件的「打开插槽」按钮）**：

```js
if (window.PluginHook && window.PluginHook.registerToolRenderHook) {
    window.PluginHook.registerToolRenderHook('afterRender', ['canvas', 'appendDraw'], function (ctx) {
        var header = ctx.header || (ctx.element && ctx.element.querySelector('.tool-call-header'));
        if (!header) return;
        if (header.querySelector('.tool-call-slot-btn')) return;   // 幂等：已加过就跳过（补挂会重复触发）
        var btn = document.createElement('button');
        btn.type = 'button';
        btn.className = 'tool-call-slot-btn';
        btn.title = '打开画布插槽';
        btn.innerHTML = '<svg viewBox="0 0 24 24" width="12" height="12" fill="none" stroke="currentColor" stroke-width="2"><rect x="3" y="4" width="18" height="16" rx="2"/></svg>';
        btn.onclick = function (e) { e.stopPropagation(); window.openCanvasSlot(); };
        header.appendChild(btn);
    });
}
```

### 7.2 页面生命周期 hook

```js
var off = PluginHook.registerHook(name, handler);   // 返回注销函数
PluginHook.unregisterHook(name, handler);
PluginHook.hooks();                                 // 控制台自省全部可用 hook
```

**通用约定**

- 同一 hook 可注册多个 handler，按**注册顺序**调用；后注册的 handler 也能收到**补挂**（`ctx.retrofit === true`）；
- **cancelable = true** 的 hook（仅 3 个：`message:before-send`、`ws:message`、`history:before-node`）：
  **任一 handler 返回 `false` → 整体取消**，调用方跳过默认行为；
- 非 cancelable hook 的返回值被忽略；
- 单个 handler 抛异常会被捕获并打日志，**不影响**其它 handler；
- 注册未知名 hook 会在控制台 `console.warn` 提示（防拼写错误），并返回空操作注销函数；
- **handler 必须幂等**：`stream:*` 每次片段都会触发；带补挂的 hook 会对存量 DOM 再触发一次；
- **高频 hook**（`stream:text` / `stream:thinking`）请保持 handler 轻量，必要时自行节流。

完整 hook 清单见 [附录](#11-附录hook-速查表)，或运行时 `PluginHook.hooks()`。

**典型示例**

```js
// 1) 拦截发送：给消息追加统一前缀，或按条件阻止发送
PluginHook.registerHook('message:before-send', function (ctx) {
    if (ctx.message === 'forbidden') {
        alert('该消息不允许发送');
        return false;                    // 取消本次发送
    }
    ctx.payload.message = '[前缀] ' + ctx.payload.message;
});

// 2) 给每条历史消息追加一个「引用」按钮（注意幂等）
PluginHook.registerHook('history:node', function (ctx) {
    var el = ctx.element;
    if (!el || el.querySelector('.my-quote-btn')) return;
    var b = document.createElement('button');
    b.className = 'my-quote-btn';
    b.textContent = '引用';
    b.onclick = function () { /* ... */ };
    el.appendChild(b);
});

// 3) 流式文本渲染后做二次加工（数学公式、关键词高亮等）
PluginHook.registerHook('stream:text', function (ctx) {
    if (!ctx.contentEl || ctx.status !== 'done') return;   // 只在片段结束时处理
    highlight(ctx.contentEl);
});

// 4) 接管自定义下行消息类型（后端推 type 为自己约定的消息）
PluginHook.registerHook('ws:message', function (ctx) {
    if (ctx.type !== 'my-custom-event') return true;   // 不关心 → 放行
    renderMyEvent(ctx.data);
    return false;                                      // 已处理 → 阻止内置分发
});

// 5) 统计到达后追加自定义指标
PluginHook.registerHook('stats:task', function (ctx) {
    if (!ctx.statsEl || ctx.statsEl.querySelector('.my-metric')) return;
    var s = document.createElement('span');
    s.className = 'agent-turn-stats-item my-metric';
    s.textContent = '自定义 ' + ctx.data.toolCallCount;
    ctx.statsEl.appendChild(s);
});
```

### 8.1 后端 `HelloTool.java`

```java
package com.agent.hopaw.tool.hello;

import com.agent.hopaw.infra.model.dto.ToolConfigItem;
import com.agent.hopaw.infra.service.IPluginResultStore;
import com.agent.hopaw.infra.service.IWebSocketBridgeService;
import com.agent.hopaw.infra.tool.AgentTool;
import com.agent.hopaw.infra.tool.ToolSecurityLevel;
import com.agent.hopaw.infra.util.InvocationParametersWrapper;
import com.alibaba.fastjson2.JSON;
import dev.langchain4j.agent.tool.P;
import dev.langchain4j.agent.tool.Tool;
import dev.langchain4j.invocation.InvocationParameters;
import org.springframework.beans.factory.annotation.Autowired;

import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.UUID;

public class HelloTool implements AgentTool {

    private static final String TOOL_NAME = "hello";

    @Autowired private IWebSocketBridgeService webSocketBridgeService;
    @Autowired private IPluginResultStore pluginResultStore;

    @Override public String getName() { return TOOL_NAME; }
    @Override public String getDescription() { return "示例插件：在浏览器前端弹出一个面板并等待用户输入"; }
    @Override public String getKeyword() { return "示例,hello,演示"; }
    @Override public String getIcon() { return "hello-tool.svg"; }

    @ToolSecurityLevel(ToolSecurityLevel.Level.SAFE)
    @Tool(value = {"打开示例面板", "在浏览器前端打开示例面板并等待用户填写内容后返回"})
    public String openHelloPanel(@P("面板标题") String title,
                                 InvocationParameters invocationParameters) {
        String requestId = UUID.randomUUID().toString();
        String userId = userId(invocationParameters, true);
        pluginResultStore.register(requestId, userId);

        Map<String, Object> cmd = new HashMap<>();
        cmd.put("toolName", TOOL_NAME);
        cmd.put("action", "open");
        cmd.put("payload", title == null ? "示例面板" : title);
        cmd.put("requestId", requestId);

        boolean ok = webSocketBridgeService.sendPluginCommand(
                userId, userId(invocationParameters, false), JSON.toJSONString(cmd));
        if (!ok) {
            return "错误：指令下发失败，请让用户确认已打开会话页面后重试。";
        }

        String result = pluginResultStore.await(requestId, IPluginResultStore.DEFAULT_TIMEOUT_SECONDS);
        return result == null ? "错误：等待用户输入超时。" : "用户输入内容：" + result;
    }

    @Override
    public Map<String, Object> invoke(Map<String, Object> params) {
        return Map.of("success", true, "message", "hello from plugin");
    }

    private String userId(InvocationParameters p, boolean wantUserId) {
        if (p == null) return null;
        InvocationParametersWrapper w = InvocationParametersWrapper.create(p);
        return wantUserId ? w.getUserId() : w.getSessionId();
    }
}
```

### 8.3 前端 `static/hello.js`

```js
(function () {
    'use strict';
    var TOOL_NAME = 'hello';

    function init() {
        if (!window.PluginHook) {
            console.warn('[hello] PluginHook 未就绪');
            return;
        }
        // 接收后端指令
        window.PluginHook.register(TOOL_NAME, onCommand);

        // 页面就绪：做一次性初始化（此时历史已渲染完的可能性更大）
        window.PluginHook.registerHook('app:ready', function () {
            console.log('[hello] page ready');
        });

        // 在工具执行列表项上加「打开面板」按钮（含历史项，靠框架补挂）
        window.PluginHook.registerToolRenderHook('afterRender', TOOL_NAME, function (ctx) {
            var header = ctx.header || (ctx.element && ctx.element.querySelector('.tool-call-header'));
            if (!header || header.querySelector('.tool-call-slot-btn')) return;   // 幂等
            var btn = document.createElement('button');
            btn.type = 'button';
            btn.className = 'tool-call-slot-btn';
            btn.title = '打开示例面板';
            btn.textContent = '▣';
            btn.onclick = function (e) { e.stopPropagation(); window.openHelloSlot(); };
            header.appendChild(btn);
        });
    }

    function onCommand(cmd) {
        if (cmd.action === 'open') {
            openPanel(cmd.payload || '示例面板');
            window.__helloRequestId = cmd.requestId;
        }
    }

    function openPanel(title) {
        var root = document.querySelector('.plugin-hello');
        if (!root) return;
        root.style.display = '';
        var t = root.querySelector('.plugin-hello-title');
        if (t) t.textContent = title;
        var input = root.querySelector('.plugin-hello-input');
        if (input) input.focus();
        // 视需要收缩会话区（可参考 tools/hopaw-tool-canvas/static/canvas.js 的 shrinkChatArea）
    }

    /** 供工具执行列表按钮调用：幂等打开插槽 */
    window.openHelloSlot = function () {
        if (!isPanelOpen()) openPanel('示例面板');
    };

    function isPanelOpen() {
        var root = document.querySelector('.plugin-hello');
        return !!root && root.style.display !== 'none';
    }

    function submit() {
        var input = document.querySelector('.plugin-hello-input');
        var rid = window.__helloRequestId;
        if (rid && window.PluginHook) {
            window.PluginHook.report(rid, input ? input.value : '');   // 回传解除后端阻塞
        }
        closePanel();
    }

    function closePanel() {
        var root = document.querySelector('.plugin-hello');
        if (root) root.style.display = 'none';
        // 未提交就关闭：也回传一个空值，避免后端死等到超时
        var rid = window.__helloRequestId;
        if (rid && window.PluginHook) { window.PluginHook.report(rid, ''); window.__helloRequestId = null; }
    }

    // 绑定按钮等
    function bind() {
        var sub = document.querySelector('.plugin-hello-submit');
        if (sub) sub.onclick = submit;
        var close = document.querySelector('.plugin-hello-close');
        if (close) close.onclick = closePanel;
    }

    if (document.readyState === 'loading') {
        document.addEventListener('DOMContentLoaded', function () { bind(); init(); });
    } else {
        bind(); init();
    }
})();
```

## 9. 调试与排错

| 场景 | 做法 |
| --- | --- |
| 查可用 hook | 浏览器控制台：`PluginHook.hooks()` |
| 查 hook 是否注册成功 | `PluginHook.dispatchHook('xxx', {})`，看 handler 是否被调用 |
| 查工具集名映射 | `window.toolOwnerSetMap`（工具名/展示名 → 工具集名） |

| 插件的静态资源不生效 | 资源 URL 带 `?v=<jar lastModified hex>`，重装/替换 jar 后版本号自动变化；确认 `plugin-assets.json` 的 `path` 确实以 `static/` 开头 |
| 看插件是否加载 | 日志里搜 `Registered plugin [...] with N tools`、`Loaded N frontend assets from ...` |
| 看下发指令是否投递 | CanvasTool/GomokuTool 日志：`send command action=... delivered=true/false` |
| 全量打包 | `mvn clean package -DskipTests` 实测可通过（21 模块 BUILD SUCCESS，含 `hopaw-plugin-repo`）。若只想快速验证主程序，仍可用 `mvn package -DskipTests -pl hopaw-app -am` |

**构建注意**

- 构建 exec jar 前建议先停应用，否则 `clean` 无法删除被占用的 jar；
- 只改静态资源（js/css/html）也可用 zip 直接替换 jar 内条目，但同样需先停应用。

## 10. 常见问题

**Q1：`getSlotOpener()` / `getXxx()` 之类的字段是不是要加在 AgentTool 上？**
不加。插件的 UI 定制请走 **hook 体系**（§7），主程序零定制：工具集渲染按钮、消息装饰、消息接管都由插件自己注册 hook 实现。

**Q2：hook 注册了但没反应？**
按顺序排查：
1. 名称是否拼错 → 控制台会有 `[plugin-hook] 未知 hook 名称：xxx`；
2. 是否在 `window.PluginHook` 就绪后才调用（插件 JS 一定晚于 plugin-hook.js，正常不会踩）；
3. 是针对**已渲染**内容吗 → 需要补挂的 hook 只有 `history:node` 和工具渲染 hook，其它 hook 不补挂；若错过时机，用 `document.addEventListener('plugin:ready', ...)` 自行扫描 DOM；
4. 是否被前一个 handler 返回 `false` 取消了（仅 cancelable hook，且会整体取消）。

**Q3：按钮加了两次 / 内容重复渲染？**
hook 会对存量 DOM 补挂，且 `stream:*` 每次片段都触发。handler 里加 DOM 前必须先判重（如 `if (el.querySelector('.my-btn')) return;`）。

**Q4：插件图标显示不出来（乱码或空白）？**
插件图标必须是 **SVG 文本**，且 `getIcon()` 返回的值不能等于默认值 `agent-tool.svg`。返回 PNG 会被当文本读出而乱码。

**Q5：工具改名后历史记录里的旧项匹配不到 hook / 显示空名？**
后端对映射不到的旧工具名会**回退原始名**（不再是 `null`）；前端注册 hook 时用**数组**写出历史别名即可命中，例如 `['canvas', 'appendDraw']`。

**Q6：多插件互相收到对方的指令？**
用 `PluginHook.register(toolName, handler)` 按工具名订阅（而不是 `onCommand`）。后端侧指令已按 `sessionId` 做会话隔离。

**Q7：前端没收到后端的插件指令？**
1. 前端连接是否建立（`/ws/plugin`）且已注册当前会话；
2. 后端 `sendPluginCommand` 返回值是否为 `true`（`false` 说明桥接异常）；
3. `sessionId` 是否与浏览器打开的会话一致（不一致会被隔离丢弃）；
4. 指令的 `toolName` 是否与前端 `register` 的一致。

**Q8：@Tool 方法一直阻塞到超时？**
前端必须回传 `PluginHook.report(requestId, value)`；用户中途关闭插槽也要回传（哪怕空串）。建议 timeout 用 `IPluginResultStore.DEFAULT_TIMEOUT_SECONDS`。
